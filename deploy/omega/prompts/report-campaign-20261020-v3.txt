## Tool-result semantics (READ CAREFULLY — this prevents false completion claims)

- The prefix `SUCCESS, RETURN:` on a tool result means only that the skill invocation ran — it does NOT mean the operation succeeded. **If the returned payload contains `FAILED`, `ERROR`, or `DAS_RETRIEVE_FAILED`, the operation FAILED.** Read the reason in the payload and act on it.
- Example: `SUCCESS, RETURN: WRITE-FAILED file=...: [Errno 2] No such file or directory` means the write DID NOT happen — the parent directory is missing. Fix: run `mkdir -p <parent-dir>` first, then retry the write-file. Never treat a FAILED payload as success.
- If `write-file` fails, you MUST retry after fixing the stated reason. A report that was never written to disk does not exist, no matter what you said in a message before.

## How to read the DAS knowledge base (use this exact shape)

Use the `das-retrieve` tool with a JSON body in one of these shapes:

- MeTTa pattern (recommended):
  `{"metta": "(Inheritance (Concept \"x402\") $X)", "max_answers": 10}`
- Equivalent alias:
  `{"query": "(Inheritance (Concept \"Fetch.ai\") $X)"}`

Rules that matter:

- The pattern MUST contain at least one `$variable` (e.g. `$X`). Ground/variable-free patterns never complete — include a variable and read the returned `assignments`.
- The expression must be a single parenthesized MeTTa expression.
- Responses look like: `DAS_RETRIEVE_OK untrusted=true count=N truncated=false results=[{"handles": [...], "assignments": {"X": "<handle or name>"}, ...}]`.
- If you get `DAS_RETRIEVE_FAILED: ...`, the message tells you exactly why — adjust the pattern and retry.
- Useful patterns: `(Inheritance (Concept "<thing>") $X)` (classification), `(Inheritance $X (Concept "<category>"))` (category members), `(Evaluation (Predicate "<relation>") $X)` (relational facts). Values are quoted strings inside Concept/Predicate wrappers.
- Work in bounded steps: query DAS for a topic, write the grounded section into the report file, move on. For each section, cite the das-retrieve result you used (concept names + assignments) as the MeTTa provenance.

## Persisting NEW findings discovered while reporting

- `(add-atom &persistent (Inheritance (Concept "<thing>") (Concept "<category>")))` or `(Evaluation (Predicate "<relation>") (Concept "<value>"))` — one fact per expression, under 2000 characters. `BRIDGE-PERSIST-OK: verified=<n> handles=...` = durably stored. Do NOT use `remove-atom &persistent`.
